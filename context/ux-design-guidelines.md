# AI-Native 读书雷达｜UX Design Guideline

## 1. 依据与访问边界

视觉参考链接 `https://mp.weixin.qq.com/s/xxKP0gzIX0-LZNWJm_zY_A` 当前无法直接访问，因此本规范不对该微信文章的具体版式细节做臆测。

本规范基于以下已确认依据生成：

- `context/system-overview.md` 中定义的产品定位、目标用户、AS-IS 瓶颈和关键假设。
- 可访问的 Thoughtworks 雷达公开资料与早期读书雷达资料所体现的结构化信息表达方式。

本规范面向全产品使用，不只约束首页，也适用于未来书单列表页、书籍详情页、推荐提交表单页等页面。

## 2. 设计判断拆解

- 为什么不能做“热闹型视觉”：产品强调长期价值和专业人群判断，视觉要传达可信、稳定、可持续，而不是热点榜单。
- 为什么不能做“重运营型页面”：目标用户需要学习路径判断，页面应降低理解成本，而不是堆入口、堆标签、堆促销式推荐。
- 为什么雷达视觉要克制：雷达承载的是结构化认知，点、圈层、领域、推荐指数都需要被快速读懂，装饰应让位于信息层级。

## 3. 风格关键词与可执行规则

| 风格关键词 | 可执行规则 |
|---|---|
| 学习路径感 | 页面优先呈现“从入门到进阶”的结构关系，而不是单本书的营销卖点；标题、筛选、详情文案都要帮助用户判断阶段与路径。 |
| 专业可信 | 使用清晰网格、稳定排版、低噪声色彩；避免夸张标语、爆款话术、大面积高饱和色。 |
| 长期价值 | 视觉节奏应像知识库/研究报告，而不是资讯流；突出“推荐理由、适合阶段、领域归属”，弱化“最新、热门、冲榜”。 |
| 可探索 | 雷达、列表、详情之间要形成轻量探索闭环：先看全局，再聚焦单本，再回到全局。 |
| 编辑感 | 通过明确标题层级、短段落、注释式说明、适度留白和稳定栏目宽度形成“被整理过的知识内容”感觉。 |

## 4. 需规避的倾向及触发原因

| 需规避倾向 | 触发设计动作 | 为什么要避免 |
|---|---|---|
| 电商感 | 使用销量榜、强 CTA 按钮、价格/购买入口优先、大面积红橙促销色 | 会把“学习路径判断”误导成“买书转化”。 |
| 社区论坛感 | 信息流瀑布、头像墙、点赞评论优先、热帖式排序 | 会削弱专业人群共建与长期价值判断。 |
| 卡通化 | 使用拟物书本插画、卡通角色、过度圆润气泡 | 与 AI 学习者需要的专业可信感冲突。 |
| 炫技式科技感 | 大面积霓虹渐变、发光粒子、深色赛博背景、动态光效过多 | 容易变成 AI 热点包装，削弱长期知识产品气质。 |
| 榜单焦虑感 | “Top 10 必读”“最火”“错过就亏”等文案和视觉强调 | 与“不追热点、强调长期价值”的定位冲突。 |

## 5. 色彩系统

| 类型 | 使用场景 | 规则 |
|---|---|---|
| 主色 | 品牌识别、关键操作、当前选中状态 | 建议使用低饱和理性蓝/青绿系，传达知识、技术、可信；不要使用强营销红。 |
| 中性色 | 页面背景、正文、辅助线、卡片边界 | 以白、近白、浅灰、深灰为主，保证长时间阅读舒适。 |
| 分类色 | 八大领域区分 | 八个领域可使用一组低饱和分类色，但只用于领域识别，不用于表达好坏。 |
| 状态色 | 推荐指数高低、错误、空态、成功 | 推荐指数使用同一色系的明度/饱和度变化，避免和领域分类色混淆。 |
| 强调色 | 少量提示、重点数字、当前焦点 | 只用于引导注意，不应同时承担分类和评分含义。 |

分类色与评分色必须分离：

- 领域分类色回答“这本书属于哪里”。
- 推荐指数色回答“这本书被专业人群多推荐”。
- 同一个点不要同时用颜色表达领域和评分；可用颜色表达领域，用大小、描边或明度表达推荐指数。

## 6. 字体与排版规范

| 层级 | 用途 | 建议 |
|---|---|---|
| 页面主标题 | 当前页面主题 | 简洁直接，避免营销口号；字号明显高于正文。 |
| 区块标题 | 雷达、列表、说明、详情等模块 | 短标题，配一句辅助说明即可。 |
| 正文 | 推荐理由、说明文本 | 控制行长，避免满屏长段；推荐理由优先 2-3 行摘要。 |
| 标签/元信息 | 领域、难度、推荐指数、作者 | 使用小字号，但对比度不能过低。 |
| 注释说明 | 图例、圈层解释、规则说明 | 语气克制，靠近对应图形或组件。 |

排版原则：

- 标题负责建立判断框架，正文负责解释原因，标签负责快速扫描。
- 大段解释不要压在首屏主视觉上。
- 行高保持宽松，给学习型内容足够呼吸感。
- 不使用过度艺术化字体，优先保持中文阅读清晰。

## 7. 间距与网格系统

| 项目 | 规则 |
|---|---|
| 页面边距 | 桌面端保持较宽左右留白，移动端保证内容不贴边。 |
| 网格 | 全站采用稳定列结构，雷达页可主区域 + 侧栏，列表页可筛选栏 + 内容区。 |
| 间距节奏 | 使用 8 的倍数建立间距节奏，如 8/16/24/32/48。 |
| 模块分隔 | 优先用留白和细线分隔，不依赖厚重卡片堆叠。 |
| 卡片使用 | 卡片只用于书籍条目、详情摘要、表单分组等明确内容容器，不做套娃卡片。 |

## 8. 通用状态视觉语言

| 状态 | 视觉规则 |
|---|---|
| 默认 | 信息完整但不过度强调，主视觉清楚，辅助信息退后。 |
| Hover | 轻微放大、描边增强或浮层摘要；不能造成布局跳动。 |
| 选中 | 使用稳定高对比描边、侧栏详情或固定详情区表达；选中状态要明显区别于 hover。 |
| 加载 | 使用骨架屏或轻量进度提示，保持页面结构可预期。 |
| 空态 | 说明当前条件下没有结果，并给出清空筛选或调整条件的行动。 |
| 错误态 | 明确说明数据暂不可用，不使用吓人的红色大面积警告。 |
| 禁用 | 降低透明度或对比度，同时保留可读性。 |

## 9. 数据可视化通用原则

| 元素 | 规则 |
|---|---|
| 点 | 一个点只代表一个对象；点的大小、描边、透明度只能表达有限含义，避免多重编码。 |
| 圈层 | 圈层表达阶段或成熟度，文字标注必须靠近图形，不能只靠图例解释。 |
| 扇区 | 扇区表达领域分类，边界要清楚但不应压过点本身。 |
| 图例 | 图例必须解释颜色、大小、圈层分别代表什么，且位置固定易找。 |
| 密集数据 | 点位重叠时优先通过聚合、轻微错位、筛选或列表联动解决，不靠缩小文字硬塞。 |
| 颜色 | 分类色与状态色分开；不要让用户猜颜色含义。 |
| 动效 | 动效只用于帮助理解状态变化，如筛选后点位淡入淡出；不做装饰性持续动画。 |

## 10. 组件复用边界

| 类型 | 必须全站统一 | 可按页面调整 |
|---|---|---|
| 色彩 | 主色、中性色、状态色语义必须统一 | 八大领域分类色可在可视化中按场景调整明度。 |
| 字体 | 字号层级、行高、标题/正文/标签关系统一 | 个别主视觉页面可适度放大标题。 |
| 按钮 | 主要/次要/文本按钮语义统一 | 页面可根据任务密度调整按钮排列。 |
| 标签 | 领域、难度、推荐指数标签样式统一 | 列表页可更紧凑，详情页可更完整。 |
| 状态 | hover、选中、加载、空态、错误态语言统一 | 具体文案按页面任务变化。 |
| 数据图形 | 点、圈层、扇区、图例的语义统一 | 不同可视化可选择不同布局方式。 |
| 卡片 | 书籍摘要卡、详情卡、表单分组的基础规则统一 | 卡片内容密度可随页面变化。 |

## 11. 参考案例可提炼但不照搬的原则

由于微信原文无法访问，以下只来自可访问的 Thoughtworks 雷达公开资料与读书雷达相关文章，不等同于对指定微信文章的直接分析：

- Thoughtworks Technology Radar 使用“点/blip + 圈层 + 分类”的结构表达复杂知识对象，适合借鉴其信息组织方式，而不是照搬其具体视觉。
- 早期读书雷达资料中提到用距离圆心表达难度层级，用不同图形表达推荐倾向，这说明雷达类图形适合把“分类、阶段、推荐态度”拆成不同视觉变量。
- 对 AI 读书雷达来说，应保留这种结构化表达，但把核心语义调整为：领域、学习阶段、推荐指数、长期价值理由。
